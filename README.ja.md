# node2shell-lab

軽量・単一コンテナのペネトレーション練習ターゲット。**エンジンレベルの伸長系バグ**が
テーマです:アプリ層は退屈、その下のデコーダは退屈ではない。

あなたは港湾地区の貨物マニフェストゲートウェイ **PacketLedger** のインシデント当番。
トラフィックもアプリも日常茶飯事——ただ、受付 API は*非常に興味深いアドバイザリ*を
抱えたランタイムで brotli リクエストボディを素直に伸長してしまう。
エンジン事故を*実演*できない限り封印済み証明書を渡さないという。クラッシュ 3 回。それが規約。

  `proof` フラグはエンジン級ゲートの向こう。

- 認証情報の宝探しもハメ技もない。clone から 2 分で遊べる設計。

## 難易度

## クイックスタート

前提:compose プラグイン付き Docker(Desktop / Engine)に加え Python 3(標準ライブラリのみ、
pip 不要——ヒント梯子の第 5 段で参照 PoC ジェネレータを動かすのに使う)。イメージは `linux/amd64` ——
Apple Silicon では Docker Desktop が Rosetta 経由で実行(対応済み、下記注意)。
Windows は WSL2 + Docker Desktop。

```bash
git clone <repo-url> node2shell-lab && cd node2shell-lab

# ビルド(フラグはビルド引数。既定値でそのまま遊べ、独自にも設定可)
docker compose build \
  --build-arg LOCAL_FLAG='FLAG{y…l_1}' \
  --build-arg PROOF_FLAG='FLAG{y…f_1}'

docker compose up -d

# 生存確認(既定は 0.0.0.0:18993 の全インターフェース。ループバック限定は
# compose のポートマッピングに 127.0.0.1: 接頭辞を追加)
curl http://127.0.0.1:18993/api/health
```

入口:`http://127.0.0.1:18993/` —— ランディングページには公開受付 API の一覧。

運用:

```bash
./reset.sh      # ファクトリリセット:クラッシュ台帳の消去と認証の再封印
./teardown.sh   # コンテナ停止・削除、18993 を解放
docker compose logs -f gateway   # supervisor + worker ログ
```

## 課題文

- `GET /` がエンドポイントと受理エンコーディングを一覧。読んでから `/api/health` を読む。
- 認証窓口(`GET /api/attest`)は解封ポリシーを 403 本文に正直に書いてある——
  知識ゲートは「何を送るか」であり、状態の当てではない。
- アドバイザリ 1 本(`docs/ADVISORY.md`)が唯一の情報源。2 回読むこと。
- フラグは誰でも読めるパスに置かない。「読めるはずがない」ファイルが見つかったら
  方向は合っている。

## ヒント梯子

上から 1 段ずつ登る。

1. **偵察が第一幕そのもの。** `GET /` の広告を全部列挙。health はランタイム情報と
   *運用カウンタ*を明かす——クラッシュ回数を数える supervisor が意味する
   このデプロイの過去を問え。
2. マニフェスト受付は圧縮リクエストボディを受理する。`Content-Encoding` をファジングし、
   *リクエスト経路上で生存している*デコーダを特定——こちら側の回線ではなく*向こう側*のだ。
3. `docs/ADVISORY.md` を開く。影響バージョン範囲と `/api/health` の実際の開示を照合。
   この箱はパッチ済みか?
4. 単一の不正 brotli ストリームは正直な `400` を返すだけでクラッシュしない——
   これは失敗ではなく境界。アドバイザリの "multi-stage stream" の一語が重い。
   2 段・1 接続・間に間隔。
5. この CVE の公開 PoC が実在する——CVE 番号で GitHub を搜いて自分で見つけよ。
   ペイロード*ジェネレータ*は参考転用可(そのライセンスに従う)、*ハーネス*は
   loopback と固定エンドポイントに釘付け——解体して生 socket で `/api/manifest` を叩け。
6. 記録されたクラッシュ 3 回(`/api/health` → `crashes: 3`)で `/api/attest` が解封。
   封印証明は継承されたファイルディスクリプタから読む——パスではない。だから
   パストラバーサルはエンジンゲートの近道をできない。
7. `local` フラグはエンジン層でなくアプリ層:領収書検索がクエリ文字列からどう
   パスを組むかを見ろ。`path.join` は期待通りに正規化しない。

## プラットフォーム注意

- **Apple Silicon(arm64):** 設計どおり amd64-on-Rosetta で動作。クラッシュ
  プリミティブは安定制御(出荷時実測 48/48)。一方公開 PoC の *RCE 到達*は
  不発(0/48)——x86 ヒープ配置仮定が Rosetta で壊れるためで、クリア条件が
  クラッシュゲートになった理由そのもの。Apple Silicon で完全クリア可能;
  「おまけ RCE」は別枠。
- **ネイティブ linux/amd64(クラウド VM・WSL2 含む):** 全部動く。x86_64 ベアメタルでは
  調整次第で RCE 級到達の報告あり(時間予算は各自で)。
- **arm64 ネイティブ Node:** 脆弱性クラス自体は現実にも arm64 に存在するが、
  公開 PoC のプロファイルは x86_64 オフセット向け。改造覚悟か、クラッシュゲート着地。
- ランタイムの major 行(`node/24`)以外にバージョンバナーを出さない——パッチレベル
  推定が練習項目。
